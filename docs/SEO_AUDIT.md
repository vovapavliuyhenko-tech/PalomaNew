| `/product.html?slug=belaya-gortenziya` | **«Товар — PALOMA»** | **`/product.html`** | **нет** | **нет** |
| `/product.html?slug=kameliya` | **«Товар — PALOMA»** | **`/product.html`** | **нет** | **нет** |
| `/blog.html` | «Блог PALOMA — цветы, кофе и вдохновение» | `/blog.html` | есть | нет |
| `/blog-article.html?id=…` | **«Статья — Блог PALOMA»** | **`/blog-article.html`** | **нет** | **нет** |

Критично: **142 адреса товаров в sitemap** отдают один и тот же пустой шаблон
с canonical на `/product.html` — для поисковика это одна страница, а не 142.
Категории отдельных страниц не имеют. Статьи блога — та же проблема, что товары.

Прочие страницы (доставка, уход, кофейня, оформление, подписка, сертификат,
контакты) — свой title и canonical, по одному H1. Исключения:
- `weddings.html` — **нет H1**;
- `coffee-item.html` — шаблон напитка (`?id=`), в sitemap как одна страница;
- `live.html` — черновик с `noindex`, но **есть в sitemap** (и файл обрезан на середине разметки).

## 7. Главное ограничение: 301 на GitHub Pages невозможен

GitHub Pages не умеет серверные редиректы, тем более по параметрам
(`product.html?slug=X`). Настоящий 301 со старых адресов возможен только при
переезде хостинга сайта на Netlify (аккаунт уже есть — там функция оплаты)
или Cloudflare. Без переезда — JS-редирект + canonical: Google его понимает,
Яндекс — хуже и дольше.
